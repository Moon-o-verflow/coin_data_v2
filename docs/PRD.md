## 1. 문서 목적과 범위

### 1.1 이 문서가 정의하는 것

- 시스템이 해결하려는 문제와 성공/실패 판정 기준
- 프로그램·LLM·사용자의 역할 경계
- 사용자 플로우와 시스템 아키텍처
- 데이터 소스별 취득 경로와 제약
- 저장소 스키마, 지표 명세, 출력 명세
- 기능 요구사항과 비기능 요구사항
- 이번 버전의 범위 밖 항목과 그 이유

### 1.2 이 문서가 정의하지 않는 것

- 매매 전략, 진입/청산 규칙, 포지션 사이징
- LLM 프롬프트 본문 (별도 문서에서 정의)
- 구현 언어의 세부 코딩 규약 (CLAUDE.md에서 정의)

### 1.3 읽는 순서

2장에서 문제를, 3~5장에서 목표와 경계를, 6~9장에서 설계를, 10~12장에서 요구사항을 정의한다. 부록 A는 계산 정의와 이벤트 목록을 정의한다. 구현자는 10장(기능 요구사항)과 11장(비기능 요구사항)을 작업 단위의 기준으로 삼는다.

## 2. 배경과 문제 정의

### 2.1 선행 버전의 구조

v2.1.x는 바이낸스 REST API에서 지표를 수집해 JSON으로 출력하고, 사용자가 이를 LLM에 붙여넣어 판단을 받는 구조였다. JSON은 원시 지표값과 OHLCV 시계열로 구성되었고, 해석과 계산 모두를 LLM이 수행했다.

### 2.2 확인된 다섯 가지 결함

**P-1. 계산 주체 오류**
가격과 지표 간 거리 계산, 확률 추정 등을 LLM이 수행했다. LLM의 산술 결과는 검증되지 않으며, 확률값은 근거 없이 생성되었다. 동일 입력에 대한 출력이 재현되지 않는다.

**P-2. 상태 부재**
각 판단이 독립적으로 수행되어 직전 판단과의 연속성이 없었다. 동일 국면에서 판단이 반복적으로 반전되었다.

**P-3. 사후 확인형 트리거**
판단 기준이 "조건 충족이 확인된 후 행동"으로 설계되어, 확인 시점에는 이미 가격이 이동한 상태였다.

**P-4. 데이터 주기 불일치**
펀딩비는 8시간 주기, 미결제약정은 24시간 변화율만 제공되어 30분~5시간 보유 구간의 판단에 사용할 수 없었다. 연속된 다수 스냅샷에서 동일 값이 반복 출력되었다.

**P-5. 지표 간 정보 중복**
RSI·MACD·볼린저밴드·이동평균은 모두 종가에서 파생되어 상호 상관이 높다. "3개 지표 정렬"이 실질적으로 단일 신호의 중복 계수였다.

### 2.3 결함과 요구사항의 대응

| 결함 | 대응 요구사항 |
|---|---|
| P-1 | 모든 수치 계산을 프로그램이 수행 (FR-3.x) |
| P-2 | 요약에 직전 요약 상태를 포함 (FR-4.4). **부분 대응**: LLM의 판단 자체는 저장하지 않는다(판단 로그는 13장 범위 밖) |
| P-3 | 이벤트에 발생 여부뿐 아니라 진행 정도를 포함 (FR-3.12) |
| P-4 | 프리미엄 인덱스 1분, 미결제약정 5분 주기 사용 (FR-1.3, FR-1.4) |
| P-5 | 지표를 계열로 분류하여 출력 (FR-3.13) |

## 3. 목표와 비목표

### 3.1 목표

- **G-1**: 판단 시점의 시장 상태를 구조화된 JSON으로 산출한다.
- **G-2**: 모든 수치를 프로그램이 계산하여 LLM의 산술 수행을 제거한다.
- **G-3**: 데이터의 결손과 갱신 시각을 명시하여 신뢰도 판단을 가능하게 한다.
- **G-4**: 이 구조가 기존 방식보다 유용한지 검증할 수 있는 최소 기능을 제공한다.

### 3.2 비목표

- **NG-1**: 매매 신호 생성. 시스템은 재료만 제공하며 방향을 제시하지 않는다.
- **NG-2**: 주문 실행. 거래소 계정 API를 사용하지 않는다.
- **NG-3**: 수익 최적화. 파라미터를 성과에 맞춰 조정하는 기능을 포함하지 않는다.
- **NG-4**: 실시간 상시 가동. 스케줄 실행과 수동 실행만 지원한다.
- **NG-5**: 알림. 이벤트 감지 후 사용자에게 통지하는 기능을 포함하지 않는다.

## 4. 검증 기준

### 4.1 검증 방법

시스템 완성 후 2~3주간 수동 요약 경로를 사용하여 판단을 수행하고, 아래 기준으로 계속 여부를 결정한다.

### 4.2 계속 판정 조건

- 요약 JSON만으로 시장 상태 파악이 가능하다.
- LLM 출력에서 근거 없는 수치가 발생하지 않는다.
- 동일 국면에서 판단의 일관성이 유지된다.
- 요약 생성부터 판단까지 소요 시간이 차트 직접 확인보다 짧다.

### 4.3 중단 판정 조건

- 요약 확인 후에도 차트를 별도 확인해야 한다.
- 요약에 누락된 정보를 수동으로 보완해야 하는 경우가 반복된다.
- 판단 결과가 실행 가능한 형태로 수렴하지 않는다.

### 4.4 검증 대상이 아닌 것

매매 성과는 이번 버전의 검증 대상이 아니다. 판단 적중률 측정은 판단 로그와 결과 라벨링이 구현된 이후 단계에서 수행한다.

## 5. 역할 경계

### 5.1 역할별 책임

| 주체 | 책임 | 산출물 |
|---|---|---|
| 프로그램 | 데이터 수집, 지표 계산, 이벤트 판정, 구조화 | JSON 요약 |
| LLM | 사실 간 관계 해석, 신호 충돌 중재, 판단 | 텍스트 판단 |
| 사용자 | 실행 결정, 주문 집행, 규칙 결정 | — |

### 5.2 경계 원칙

- **B-1**: 수치는 프로그램만 생성한다. LLM은 프로그램이 산출한 수치를 인용하며, 새로운 수치를 만들지 않는다.
- **B-2**: 프로그램은 방향을 제시하지 않는다. 이벤트 발생 여부와 측정값만 출력하며, 매수/매도 판정을 포함하지 않는다.
- **B-3**: 실행 권한은 단방향이다. 프로그램과 LLM은 거래소에 대한 쓰기 권한을 갖지 않는다.
- **B-4**: 검증된 판단 규칙은 코드로 이관한다. LLM이 반복 수행하는 판단 중 검증된 것은 후속 버전에서 프로그램 계산으로 전환한다.

## 6. 사용자 플로우

### 6.1 UF-1: 초기화

**목적**: 저장소를 최초 구축한다.

**입력**: 적재 기간 (설정 파일 기본값 사용 가능). 기본 기간은 부록 A의 워밍업 요구 구간(가장 긴 타임프레임 × 가장 긴 룩백) 이상이어야 한다. 예: 1일 봉 Parkinson(20)의 백분위(룩백 100)만으로도 최소 119일이 필요하다.

**처리**
1. 저장소 스키마 생성
2. 아카이브에서 지정 기간의 일별 파일 다운로드 (klines, premiumIndexKlines, metrics)
3. 파일별 체크섬 검증, 압축 해제, 파싱, 시간순 정렬
4. 저장소에 적재 (중복은 기본키로 차단, metrics는 컬럼 단위 병합 — FR-1.7)
5. 파일별 적재 결과를 `archive_file`에 기록
6. 아카이브 미제공 구간(최근 1~2일)을 REST로 보완
7. 결측 구간을 탐지하여 기록

**출력**: 적재 결과 요약 (데이터셋별 행 수, 기간, 결측 구간 수)

**실패 처리**: 중단 후 재실행 시 `archive_file`에 적재 완료로 기록된 파일을 건너뛰고 이어서 수행한다.

### 6.2 UF-2: 증분 수집

**목적**: 저장소를 최신 상태로 유지하여 `summary`의 실행 시간을 줄이고, 아카이브 빈칸을 REST 보관 기간(30일) 안에 보완한다.

**실행**: 수동 실행. OS 스케줄러 등록은 선택 사항이다. 스케줄 없이 운용해도 데이터는 유실되지 않는다.

**처리**
1. 데이터셋별 마지막 적재 시각 조회
2. 그 이후 구간 중 아카이브가 공개된 일자는 아카이브로, 나머지(최근 1~2일)는 REST로 적재한다. 장기간 실행하지 않아 REST 보관 기간(metrics 30일)을 넘긴 경우에도 아카이브로 복구된다.
3. 저장소에 적재
4. 결측 탐지 및 기록
5. 실행 이력 기록

**출력**: 없음 (로그만 기록)

**실패 처리**: 실패를 로그에 기록하고 종료한다. 다음 실행이 미적재 구간을 보완한다.

**근거**: v3 범위의 데이터 3종(1분봉, 프리미엄 인덱스, metrics)은 모두 아카이브에 영구 보관되므로 주기 수집이 없어도 유실되지 않는다. 주기 수집이 유실 방지에 필수인 것은 체결(REST 24시간)과 청산이며, 둘 다 13장 범위 밖이다.

### 6.3 UF-3: 수동 요약 생성

**목적**: 판단 시점의 시장 상태를 산출한다.

**입력**: 없음 (실행 명령만)

**처리**
1. UF-2와 같은 절차로 저장소 갱신 (마감 봉만 저장)
2. 진행 중인 1분봉과 펀딩 정보를 REST로 조회 (저장하지 않음)
3. 계산 대상 구간을 저장소에서 로드
4. 1분봉으로 상위 타임프레임 봉 합성
5. 지표·구조·레짐·레벨 계산
6. 이벤트 판정
7. 직전 요약 정보 조회
8. JSON 요약 조립 및 파일 저장

**출력**: JSON 파일 경로, 요약 ID, 기준 시각

**실패 처리**: 일부 데이터 취득 실패 시에도 요약을 생성하며, 결손을 요약 내에 명시한다.

### 6.4 UF-4: 상태 점검

**목적**: 저장소의 적재 상태와 결손을 확인한다.

**입력**: 없음

**처리**: 데이터셋별 적재 기간, 행 수, 결측 구간, 최종 갱신 시각을 조회한다.

**출력**: 상태 보고 (표준 출력)

## 7. 시스템 아키텍처

### 7.1 계층 구조

```
[5] cli      흐름 조립 (ingest 결과를 store에 적재, compute·report 호출)
[4] report   요약 조립, JSON 직렬화
[3] compute  지표, 구조, 레짐, 레벨, 이벤트 판정
[2] store    저장소 읽기/쓰기, 결측 관리
[1] ingest   아카이브 다운로드, REST 클라이언트, 응답 파싱
             바이낸스 (아카이브 / REST API)

공용: config (설정·기본값·API 제약 상수), models (계층 간 데이터 구조)
```

### 7.2 의존 방향 규칙

- 상위 계층은 하위 계층 어디든 참조할 수 있다. 역방향 참조는 금지한다.
- 예외: `ingest`와 `store`는 서로 참조하지 않는다. 둘 사이의 데이터 이동은 `cli`가 수행한다.
- `config`와 `models`는 모든 계층이 참조할 수 있으며, 어떤 계층도 참조하지 않는다.

| 모듈 | 참조 가능 |
|---|---|
| `cli` | report, compute, store, ingest, config, models |
| `report` | compute, store, config, models |
| `compute` | store(조회 인터페이스), config, models |
| `store` | config, models |
| `ingest` | config, models |
| `config`, `models` | 표준 라이브러리만 |

- `compute`는 데이터의 출처(아카이브/REST/실시간)를 인지하지 않는다.
- `ingest`는 지표 정의를 인지하지 않는다.

**근거**: 후속 버전에서 실시간 수집기를 추가할 때 `ingest`와 `store`만 확장하면 되며, `compute` 이상은 변경되지 않는다.

### 7.3 확장 지점

| 후속 기능 | 삽입 계층 |
|---|---|
| 실시간 체결/청산 수집 | ingest, store |
| 판단 로그 및 결과 라벨링 | store, report |
| base rate 통계 | compute (신규 모듈) |
| 이벤트 감지 및 알림 | compute와 report 사이 |

| `/fapi/v1/klines` | limit 비례 | 구현 상한 1000 (아래 주 참조) |
| `/fapi/v1/premiumIndexKlines` | limit 비례 | 구현 상한 1000 |
| `/futures/data/openInterestHist` | 0 | period 5m 이상, limit 최대 500, **최근 30일만 제공**, IP당 5분간 1000회 |
| `/futures/data/topLongShortPositionRatio` | 0 | period 5m 이상, 최근 30일 |
| `/futures/data/topLongShortAccountRatio` | 0 | 동일 |
| `/futures/data/globalLongShortAccountRatio` | 0 | 동일 |
| `/futures/data/takerlongshortRatio` | 0 | 동일 |
| `/fapi/v1/premiumIndex` | 공식 문서 확인 필요 | 인증 불필요, 조회 시점 스냅샷 |
| `/fapi/v1/aggTrades` | 20 | **24시간 이내만 조회 가능**, startTime/endTime 동시 지정 시 간격 1시간 미만, limit 최대 1000 |

**전역 제약**: USD-M 선물 REST는 IP당 분당 요청 가중치 2400. `/futures/data/*`의 "IP당 5분간 1000회"는 가중치와 별개의 요청 횟수 한도다.

**klines limit 주**: 공식 SDK 주석은 최대 1000, 문서 사본은 최대 1500(가중치 1000 이하 5, 1000 초과 10)으로 엇갈린다. 공식 문서 확인 전까지 1000을 상수로 사용한다(15.6).

### 8.3 aggTrades의 구조적 특성

공식 문서에 따르면 `/fapi/v1/aggTrades`는 시장 체결만 집계하며, **보험기금 체결과 ADL 체결은 포함하지 않는다**.

**영향**: 공개 체결량은 오프북으로 처리된 강제 청산 물량을 구조적으로 제외한다. 따라서 미결제약정 감소분과 공개 체결량의 괴리는 오프북 청산 규모의 간접 지표로 사용할 수 있다. 이 로직은 후속 단계(체결 수집, 13장)에서 구현한다.

### 8.4 아카이브 파일 특성

아래 수치는 2026-09-24에 ETHUSDT 아카이브 원본을 조사한 결과다. metrics는 전체 기간(2021-12-01~2026-09-22, 1,757일), klines와 premiumIndexKlines는 2025-09-01~2026-09-22(387일)를 조사했다.

**klines 데이터셋**
- 시각 컬럼(`open_time`, `close_time`)은 UTC 밀리초 정수다. `close_time = open_time + 59999`.
- **헤더 행 유무가 파일마다 다르다.** 2021년 파일은 헤더가 없고 최근 파일은 헤더가 있다. 첫 줄을 판별해 처리한다.
- 조사 구간에서 누락된 분은 0개였다.

**metrics 데이터셋**
- 컬럼: `create_time`, `symbol`, `sum_open_interest`, `sum_open_interest_value`, `count_toptrader_long_short_ratio`, `sum_toptrader_long_short_ratio`, `count_long_short_ratio`, `sum_taker_long_short_vol_ratio`
- **`create_time`은 `YYYY-MM-DD HH:MM:SS` 형식의 UTC 문자열이다.** 정수 밀리초로 변환하여 저장하며, 부동소수점을 거치지 않는다.
- 간격: 5분 (조사 구간에서 5분 격자를 벗어난 시각 없음, 중복 시각 없음)
- **행이 시간순으로 정렬되어 있지 않을 수 있다.** 1,757개 파일 중 133개가 비정렬이며, 2026-08-11 이후 파일은 전부 비정렬이다. 적재 전 정렬이 필수다.
- **행 결측은 드물다.** 1,757일 중 9일, 총 140행이 누락되었고 그중 125행이 2024-02-16 하루에 있다.
- **행은 있으나 값이 빈 칸인 경우가 많다.** 빈 문자열은 NULL로 적재한다.

| 컬럼 | 빈 칸 발생 일수 | 기간 |
|---|---|---|
| `count_toptrader_long_short_ratio` | 335일 | 2021-12-30 ~ 2025-07-22 |
| `sum_toptrader_long_short_ratio` | 333일 | 2021-12-30 ~ 2025-07-21 |
| `sum_taker_long_short_vol_ratio` | 134일 | 2021-12-30 ~ 2022-09-14 |
| `count_long_short_ratio` | 31일 | 2021-12-30 ~ 2025-07-21 |

**metrics 컬럼 매핑**

| 아카이브 컬럼 | REST 엔드포인트 / 필드 | `metrics_5m` 컬럼 |
|---|---|---|
| `create_time` | `timestamp` | `ts` |
| `sum_open_interest` | `openInterestHist` / `sumOpenInterest` | `sum_open_interest` |
| `sum_open_interest_value` | `openInterestHist` / `sumOpenInterestValue` | `sum_open_interest_value` |
| `sum_toptrader_long_short_ratio` | `topLongShortPositionRatio` / `longShortRatio` | `top_position_ratio` |
| `count_toptrader_long_short_ratio` | `topLongShortAccountRatio` / `longShortRatio` | `top_account_ratio` |
| `count_long_short_ratio` | `globalLongShortAccountRatio` / `longShortRatio` | `global_account_ratio` |
| `sum_taker_long_short_vol_ratio` | `takerlongshortRatio` / `buySellRatio` | `taker_buy_sell_ratio` |

이 매핑은 컬럼명과 값의 범위로 추정한 것이며 공식 문서로 확인되지 않았다. 구현 시 아카이브와 REST가 겹치는 구간(최근 30일)에서 값을 대조하여 검증한다(15.7).

**premiumIndexKlines 데이터셋**
- 구조와 시각 형식은 klines와 동일하나 `volume`, `quote_volume`, `taker_buy_volume`, `taker_buy_quote_volume`이 0이다.
- 사용 컬럼은 `open`, `high`, `low`, `close`에 한정한다.
- `count` 필드는 1분 내 샘플 수다. 대부분 12이며, 조사 구간 557,280개 봉 중 229개가 12 미만이었다.
- 값은 프리미엄 비율이며 음수를 가질 수 있다. 조사 구간에서 1분봉 종가의 99.2%가 음수였다.
- 조사 구간에서 누락된 분은 0개였다.

**공통**
- 밀리초 시각을 스프레드시트로 열면 지수 표기로 손실된다.
- 각 파일에 `.CHECKSUM` 동반 파일이 존재한다. 형식은 `<sha256 16진수>  <파일명>`이다.
- 공개 시점은 해당 UTC 일자 종료 이후이며, 1~2일 지연을 가정한다. (2026-09-24 01:53 UTC 기준 2026-09-22분까지 공개)

### 8.5 청산 데이터 취득 불가

| 경로 | 상태 |
|---|---|
| 아카이브 `liquidationSnapshot` (USD-M) | 2026-09 기준 ETHUSDT 파일이 과거분을 포함해 존재하지 않음 |
| REST `allForceOrders` | 인증 필요 |
| WebSocket `@forceOrder` | 실시간 전용, 소급 불가 |

**결론**: 청산 데이터는 실시간 수집을 시작한 시점 이후만 존재하며 과거 복원이 불가능하다. 이번 버전은 청산 없이 동작하며, 청산 의존 로직(유동성 사냥 3조건 판정, 청산 밀도)은 범위에서 제외한다.

### 8.6 시각 기준

- 모든 시각은 UTC 밀리초 정수로 저장한다.
- 표시가 필요한 경우에만 변환한다.
- 시스템 시계 오차는 `/fapi/v1/time`으로 확인 가능하나, 이번 버전에서는 보정하지 않고 `ingest_run.detail`에 기록만 한다.
- 봉의 마감 여부는 서버 시각 기준으로 판정한다. `close_time < 서버 시각`인 봉만 마감 봉이다.

### 9.1 저장소 선택

SQLite 단일 파일을 사용한다.

**근거**: 결측 탐지, 중복 차단, 갱신 주기가 다른 데이터셋의 시각 기준 결합이 필요하다. 파일 기반 저장은 이 세 가지를 매번 전체 스캔으로 처리해야 한다. 서버형 RDBMS는 운영 부담 대비 이점이 없다.

## 10. 기능 요구사항

### 10.1 수집 (ingest)

**FR-1.1 아카이브 다운로드**
지정 기간의 일별 아카이브 파일을 임시 경로에 다운로드하고 `.CHECKSUM`으로 무결성을 검증한다. 검증 실패 시 해당 파일을 폐기하고 재시도하며, 재시도 실패 시 `archive_file`에 `checksum_failed`로, `data_gap`에 `checksum_failed`로 기록한다. 파일이 없으면(HTTP 404) `archive_file`에 `not_published`로 기록한다. 결과는 파일마다 `archive_file`에 기록한다.

**FR-1.2 아카이브 파싱**
압축 해제 후 CSV를 파싱한다.
- 첫 줄이 헤더인지 판별하여 헤더 유무와 관계없이 파싱한다.
- 시각은 정수 밀리초로 변환하며 부동소수점 변환을 거치지 않는다. klines·premiumIndexKlines는 정수 그대로, metrics의 `create_time`은 UTC 문자열을 변환한다.
- 빈 문자열은 NULL로 파싱한다. 0으로 바꾸지 않는다.
- 시각 기준 오름차순 정렬 후 적재한다.

**FR-1.3 REST 수집 — 봉 데이터**
`/fapi/v1/klines`와 `/fapi/v1/premiumIndexKlines`에서 마지막 적재 시각 이후 구간을 요청한다. 요청당 건수 상한(상수, 8.2)에 따라 분할 요청한다. 응답 중 **마감된 봉만 적재**하고, 진행 중인 봉은 적재하지 않고 호출자에게 별도로 반환한다.

**FR-1.4 REST 수집 — 파생 지표**
`/futures/data/openInterestHist`, `topLongShortPositionRatio`, `topLongShortAccountRatio`, `globalLongShortAccountRatio`, `takerlongshortRatio`에서 5분 주기 데이터를 요청하여 `metrics_5m`에 컬럼 단위로 병합 적재한다(FR-1.7). 각 엔드포인트의 응답 시각이 일치하지 않을 수 있으므로 시각 기준 결합한다. 한 엔드포인트가 실패해도 나머지는 적재하며, 실패한 컬럼은 `data_gap`에 컬럼 단위로 기록한다.

**FR-1.5 요청 한도 제어**
응답 헤더의 사용 가중치를 추적하여 분당 한도(2400) 초과를 방지한다. 한도의 설정 가능한 비율(기본 70%)에 도달하면 요청을 지연한다. `/futures/data/*`는 가중치와 별도로 5분간 요청 횟수를 세어 한도(1000회)의 같은 비율에서 지연한다. HTTP 429 수신 시 `Retry-After`를 준수한다.

**FR-1.6 재시도**
네트워크 오류와 5xx 응답에 대해 지수 백오프로 재시도한다. 최대 재시도 횟수는 설정값을 따른다. 4xx(429 제외)는 재시도하지 않는다.

**FR-1.7 경계 처리**
아카이브와 REST의 취득 구간이 겹칠 경우 양쪽 모두 적재를 시도한다.
- `kline_1m`, `premium_index_1m`(마감 봉만 저장): 기본키 충돌 시 기존 행을 유지한다.
- `metrics_5m`: 기본키 충돌 시 기존 행의 NULL 칸만 새 값으로 채우고, NULL이 아닌 값은 유지한다.

**FR-1.8 펀딩 정보 조회**
`summary` 실행 시 `/fapi/v1/premiumIndex`에서 현재 펀딩비(`lastFundingRate`)와 다음 펀딩 시각(`nextFundingTime`)을 조회한다. 저장소에 저장하지 않는다. 조회 실패 시 해당 필드는 `null`이며 `gaps`에 `rest_failed`로 기록한다. 응답의 마크 가격은 사용하지 않는다.

### 10.2 저장 (store)

**FR-2.1 멱등 적재**
동일 데이터를 반복 적재해도 결과가 변하지 않는다.

**FR-2.2 결측 탐지**
적재 후 데이터셋별 기대 간격(1분, 5분)에 대해 결측을 산출하여 `data_gap`에 기록한다.
- 행 단위: 누락된 시각을 `field = '*'`로 기록한다.
- 컬럼 단위: 행은 있으나 NULL인 칸을 컬럼별로 기록한다(`metrics_5m`).
- 탐지 범위의 끝은 마지막 마감 시각이다. 아직 마감되지 않은 구간은 결측이 아니다.
- 같은 미해소 결측을 중복 기록하지 않는다.
- 후속 적재로 결측이 전부 해소되면 `resolved_at`을 갱신한다. 일부만 해소되면 기존 행을 해소 처리하고 남은 구간을 새 행으로 기록한다.
- reason은 `cli`가 전달한 수집 결과(`archive_file` 상태, REST 실패 여부, 기준 시각)로 판정한다. store는 결측의 원인을 추정하지 않는다. 판정 규칙은 12.2를 따른다.

**FR-2.3 결측 비보간**
결측 구간에 대해 보간, 전방 채우기, 기본값 삽입을 수행하지 않는다.

**FR-2.4 적재 이력**
모든 수집 실행을 `ingest_run`에 기록한다.

**FR-2.5 상태 조회**
데이터셋별 적재 기간, 행 수, 미해소 결측 구간, 최종 갱신 시각을 조회하는 인터페이스를 제공한다.

**FR-2.6 파일 단위 적재 기록**
아카이브 파일마다 `archive_file`에 결과를 기록한다. 한 파일의 적재는 단일 트랜잭션으로 수행하고, 트랜잭션이 커밋된 뒤에만 `loaded`로 기록한다. `init` 재개 시 `loaded` 파일은 건너뛰고, `not_published`·`checksum_failed` 파일은 다시 시도한다.

### 10.3 계산 (compute)

각 지표·이벤트의 정확한 정의(공식, 초기값, 동점 처리, 기본값)는 부록 A에서 정의한다. 부록 A가 확정되기 전에는 해당 지표를 구현하지 않는다.

**FR-3.0 결손 표시**
결손은 불리언이 아니라 비율로 표기한다. 지표값마다 계산 창 안의 결손 비율(누락 1분봉 수 / 기대 1분봉 수)을 함께 산출한다. 봉 단위가 아니라 분 단위로 센다(A.1.3). 이전 값을 이어받는 지표(Wilder 평활 등)도 계산 창 길이를 기준으로 판정하여, 결손 표시가 창 밖으로 영구히 이어지지 않게 한다.

**FR-3.1 봉 합성**
1분봉으로 15분·30분·1시간·1일 봉을 합성한다. 봉 경계는 UTC 기준이다(1일 봉은 00:00 UTC 시작). 합성 봉마다 누락된 1분봉 수를 기록한다. 진행 중인 미완성 봉은 완성 봉과 구분하여 표시한다.

**FR-3.2 변동성 지표**
ATR(기본 14)과 Parkinson 변동성(기본 20)을 타임프레임별로 산출한다. Parkinson 변동성의 백분위 순위를 설정된 룩백(기본 100) 기준으로 산출한다.

**FR-3.3 스윙 구조**
ATR 기반 ZigZag로 스윙 고점·저점을 식별한다. 반전 임계값은 `k × ATR_{t−1}`(직전 봉 ATR, A.1.7)이며 `k`는 설정값(기본 2.0)이다. 알고리즘은 A.3.2를 따른다. 확정된 극점과 미확정 진행 파동을 분리하여 출력한다.

**FR-3.4 구조 전환**
아직 돌파되지 않은 최근 확정 스윙 극점을 종가 기준으로 돌파하면, 돌파 방향과 구조 상태(A.3.3)에 따라 분류한다. 구조 상태와 같은 방향의 돌파는 BOS, 반대 방향의 돌파는 MSS다. MSS는 돌파 봉의 몸통이 최근 N봉(기본 20) 평균 몸통의 배수(기본 1.5) 이상일 때만 성립한다. 변위를 충족하지 못한 반대 방향 돌파와 구조 상태가 정해지지 않은 돌파는 별도 값으로 표기한다(A.3.4).

**FR-3.5 되돌림**
확정된 직전 파동에 대해 되돌림 깊이(직전 파동 범위 대비 비율)와 시간 비율(조정 봉 수 / 동인 파동 봉 수)을 산출한다. 되돌림 깊이는 0~1로 자르지 않는다. 파동 시작점을 넘으면 1 초과, 파동 극점을 넘으면 0 미만 값을 그대로 출력한다.

**FR-3.6 캔들 구조**
봉별 위꼬리·아래꼬리·몸통 비율과, 몸통 크기의 ATR 대비 배수를 산출한다. 최근 N봉(설정값) 분량을 출력한다. 고가와 저가가 같은 봉(범위 0)의 비율과 ATR이 0일 때의 배수는 `null`이다.

**FR-3.7 레짐 판정**
레짐을 두 개의 독립 축으로 출력한다. 두 축을 하나의 레이블로 합성하지 않는다(A.4).
- 효율성 축: Kaufman Efficiency Ratio(기본 10)로 `trend`, `range`, `transition` 중 하나.
- 변동성 축: Parkinson 백분위로 `expansion`, `normal`, `compression` 중 하나.

각 타임프레임별로 두 축의 상태와 각각의 지속 봉 수를 출력한다.

**FR-3.8 충격 상태 판정**
큰 봉의 꼬리 비율이 임계값 이상이거나, 짧은 봉 간격 안에 스윙 고점과 저점이 모두 종가 돌파된 경우 `shock` 상태로 판정한다. shock이 활성인 동안 효율성 축을 `shock`으로 덮어쓰며, 변동성 축은 덮어쓰지 않는다. 판정 조건, 대상 타임프레임, 지속 기간은 A.4.4를 따른다. v1.1의 "1~2봉 내 반대 방향 MSS" 조건은 사실상 발동하지 않아 A.4.4의 조건으로 바꿨다.

**FR-3.9 파생 지표**
프리미엄 인덱스는 최신 1분 값(bp), 기간별 변화량(bp 차이), 15분 평활값의 최근 7일 분포 대비 백분위를 산출한다(A.5.2). 프리미엄 값이 0 근처이고 대부분 음수이므로(8.4) 비율 변화율과 0 기준 부호 전환은 사용하지 않는다. 계약 수 기준 미결제약정의 변화와 가격 변화를 결합해 4분면 상태를 판정한다. **명목 미결제약정을 방향성 판단에 사용하지 않는다.**

**FR-3.10 레벨 후보 산출**
15m·1h 확정 스윙 극점, 24시간 롤링 VWAP, 24시간 고저에서 레벨 후보를 도출한다. 거리와 폭은 기준 시각의 1h ATR로 정규화한다(A.7). 각 레벨은 `[중심 ± w × ATR]` 구간으로 표현하며 `w`는 설정값(기본 0.25)이다. 중심 간 거리가 설정값(기본 0.5 ATR) 미만인 레벨은 병합하고 병합된 근거 수를 기록한다. 출력하는 레벨 수의 상한은 설정값으로 둔다.

**FR-3.11 레벨 강도 미산출**
이번 버전은 레벨 강도 점수를 산출하지 않는다. 레벨 목록과 근거 종류, 정규화 거리만 출력한다.

**FR-3.12 이벤트 판정**
이벤트는 발생 여부와 함께 측정값을 갖는다. 최소 공통 필드는 발생 시각, 경과 봉 수, 관련 타임프레임이며, 유형별로 침투 깊이(ATR 배수), 거래량 배수, 지속 봉 수를 포함한다. 이벤트 유형 목록과 유형별 발생 조건·측정값·보고 기간·계열은 A.8을 따른다.

**FR-3.13 계열 분류**
모든 지표와 이벤트는 `price_structure`, `regime`, `derivatives`, `level` 중 하나의 계열로 분류되어 출력된다. 펀딩 정보(FR-1.8)는 판단 지표가 아니라 비용 정보이므로 계열 분류 대상이 아니다.

**FR-3.14 확률 미산출**
시스템은 확률, 승률, 기대값을 산출하지 않는다. 해당 필드는 통계 기능 구현 이전까지 존재하지 않는다.

### 10.4 요약 (report)

**FR-4.1 요약 구조**
요약 JSON은 다음 섹션으로 구성된다.

| 섹션 | 내용 |
|---|---|
| `meta` | 요약 ID, 생성 시각, 트리거 종류, 종목, 기준 시각, 기준 가격, 현재가, 스키마 버전, 사용 파라미터 |
| `data_freshness` | 데이터셋별 최종 갱신 시각과 기준 시각 대비 경과 |
| `price_structure` | 스윙, BOS/MSS, 되돌림, 캔들 구조 |
| `regime` | 타임프레임별 효율성 상태·변동성 상태와 각각의 지속 봉 수, ER·백분위 원값, shock 활성 여부 |
| `derivatives` | 프리미엄 인덱스(최신 bp, 변화량, 15분 평활 백분위), 계약 수 OI와 4분면, 롱숏 비율 |
| `funding` | 현재 펀딩비, 다음 펀딩 시각, 기준 시각부터 다음 펀딩까지 남은 시간 (비용 정보) |
| `levels` | 레벨 목록, 구간, 근거, 정규화 거리 |
| `events` | 판정된 이벤트 목록과 측정값 |
| `state` | 직전 요약 ID와 생성 시각, 직전 대비 주요 변화 |
| `statistics` | 통계 미구현 표시 |
| `gaps` | 계산 구간 내 결측과 취득 실패 |
| `unavailable` | 이번 버전에서 제공되지 않는 데이터와 사유 |

**기준 시각과 기준 가격**
- 기준 시각(`ref_time`): 마지막 마감 1분봉의 `close_time + 1` (다음 분의 시작 시각).
- 기준 가격(`ref_price`): 마지막 마감 1분봉의 종가. 모든 지표가 마감 봉 기준으로 계산되므로, 정규화 거리 등 모든 계산은 이 값을 기준으로 한다.
- 현재가(`current_price`): 진행 중인 1분봉의 종가를 별도 필드로 병기하고 `is_closed: false`로 표시한다. 계산에 사용하지 않는다. 조회 실패 시 `null`이다.
- 마크 가격은 사용하지 않는다.

**FR-4.2 결손 표기**
값이 없는 경우와 값이 0인 경우를 구분한다. 없는 값은 `null`로 표기하고 `gaps` 또는 `unavailable`에 사유를 기록한다.

**FR-4.3 갱신 시각 표기**
각 데이터 출처의 최종 갱신 시각을 요약에 포함한다. 갱신 시각이 기준 시각과 설정값 이상 차이나면 `data_freshness`에 경고 표시를 부여한다.

**FR-4.4 상태 연속성**
직전 요약의 ID와 생성 시각을 포함한다. 직전 요약이 존재하면 주요 상태값(레짐, 구조, 4분면)의 변화 여부를 기록한다. 비교에는 `summary_log.state`를 사용한다. 직전 요약과 `params_hash`가 다르면 파라미터가 바뀌었음을 표시한다.

**FR-4.5 요약 저장**
생성된 요약을 파일로 저장하고 `summary_log`에 기록한다. 요약 ID는 생성 시각의 UTC 표기(`YYYYMMDDTHHMMSSZ`)이며, 파일명은 요약 ID를 포함한다.

**FR-4.6 부분 실패 시 생성**
일부 데이터 취득에 실패해도 요약을 생성한다. 실패한 데이터의 필드는 `null`이며 `gaps`에 사유가 기록된다.

### 10.5 인터페이스 (CLI)

**FR-5.1 명령 구성**
`init`, `sync`, `summary`, `status` 네 개의 하위 명령을 제공한다.

| 명령 | 대응 플로우 |
|---|---|
| `init` | UF-1 초기화 |
| `sync` | UF-2 증분 수집 (수동 또는 선택적 스케줄) |
| `summary` | UF-3 수동 요약 |
| `status` | UF-4 상태 점검 |

**FR-5.2 종료 코드**
정상 종료 0, 부분 실패 1, 실행 불가 2를 반환한다. 스케줄러가 결과를 판별할 수 있어야 한다. 부분 실패는 **이번 실행에서** 데이터 취득에 실패한 경우만 해당한다. 원본 자체의 결측(`source_gap`)이나 이전부터 있던 미해소 결측은 부분 실패로 보지 않는다.

**FR-5.3 진행 표시**
`init`은 장시간 실행되므로 진행 상황을 출력한다. `sync`는 비대화형 실행을 전제로 출력을 최소화한다.

### 10.6 설정

**FR-6.1 설정 파일**
모든 파라미터를 단일 설정 파일에서 관리한다. 형식은 TOML이며 표준 라이브러리 `tomllib`로 읽는다. 섹션 구분: `data`, `indicators`, `regime`, `levels`, `events`, `report`, `runtime`.

**FR-6.2 기본값**
모든 설정 항목은 기본값을 가지며, 설정 파일 없이도 실행 가능하다.

**FR-6.3 하드코딩 금지**
지표 기간, 임계값, 배수, 룩백 등 조정 가능한 수치를 코드에 직접 기술하지 않는다.

**FR-6.4 설정 기록**
요약 생성 시 사용된 주요 파라미터와 그 해시를 `meta`에 포함한다. 파라미터 변경 전후의 요약을 구분할 수 있어야 한다.

## 11. 비기능 요구사항

### 11.1 정확성

**NFR-1.1** 지표 계산은 동일 입력에 대해 동일 출력을 산출한다.
**NFR-1.2** 시각 연산에서 부동소수점을 사용하지 않는다. 모든 시각은 정수 밀리초다.
**NFR-1.3** 결측 데이터가 계산에 포함될 경우 해당 지표에 결손 표시를 부여하며, 결측을 0 또는 직전값으로 대체하지 않는다.
**NFR-1.4** 합성 봉은 원본 1분봉의 결측 여부를 승계한다.

### 11.2 성능

**NFR-2.1** `summary` 실행은 정상 조건에서 30초 이내에 완료한다. 정상 조건은 저장소의 마지막 적재가 기준 시각으로부터 설정값(기본 2일) 이내인 경우다. 그보다 오래되면 증분 수집에 시간이 더 걸릴 수 있으며, 이 경우 소요 시간을 제한하지 않는다.
**NFR-2.2** `sync` 실행은 정상 조건에서 60초 이내에 완료한다.
**NFR-2.3** `init`의 소요 시간은 제한하지 않되, 중단 후 재개가 가능해야 한다.
**NFR-2.4** 계산 대상 구간은 설정값으로 제한하며, 전체 저장소를 스캔하지 않는다.

### 11.3 신뢰성

**NFR-3.1** 부분 실패 시 시스템은 사용 가능한 결과를 산출한다.
**NFR-3.2** 수집 중단 시 저장소는 일관된 상태를 유지한다. 아카이브 파일은 임시 경로에 받아 체크섬 검증 후에만 파싱하며, 한 파일의 적재는 단일 트랜잭션으로 수행한다. 중단된 파일은 `loaded`로 기록되지 않으므로 재실행 시 다시 적재된다.
**NFR-3.3** 동일 명령의 반복 실행이 데이터를 손상시키지 않는다.
**NFR-3.4** 외부 API 장애가 저장소 무결성에 영향을 주지 않는다.
**NFR-3.5** 저장소에 쓰는 명령(`init`, `sync`, `summary`)은 동시에 하나만 실행된다. 프로세스 잠금을 획득하지 못하면 대기하지 않고 종료 코드 2로 종료하며, 사유를 출력한다. `status`는 읽기 전용이므로 잠금 없이 실행할 수 있다.

### 11.4 관측성

**NFR-4.1** 모든 외부 요청은 엔드포인트, 파라미터 범위, 응답 상태, 소요 시간을 로그에 기록한다.
**NFR-4.2** 결측 탐지 결과는 로그와 저장소 양쪽에 기록한다.
**NFR-4.3** 로그 수준은 설정으로 조정 가능하다.
**NFR-4.4** `status` 명령으로 저장소 상태를 코드 수정 없이 확인할 수 있다.

### 11.5 확장성

**NFR-5.1** 신규 데이터 소스 추가 시 `compute` 이상 계층을 변경하지 않는다.
**NFR-5.2** 신규 지표 추가 시 기존 지표 계산을 변경하지 않는다.
**NFR-5.3** 종목 확장 시 스키마를 변경하지 않는다.
**NFR-5.4** 요약 스키마에 버전 필드를 포함하여 후속 변경을 식별 가능하게 한다.

### 11.6 유지보수성

**NFR-6.1** 계층 간 의존 방향을 위반하는 참조를 금지한다.
**NFR-6.2** 외부 API의 제약값(한도, 보관 기간, 요청 간격)은 상수 또는 설정으로 명시하며 코드 내에 산재시키지 않는다.
**NFR-6.3** 의존 패키지는 최소화한다.

### 11.7 보안

**NFR-7.1** 인증이 필요한 엔드포인트를 사용하지 않는다. API 키를 취급하지 않는다.
**NFR-7.2** 시스템은 거래소에 대한 쓰기 요청을 수행하지 않는다.

### 11.8 이식성

**NFR-8.1** 저장소는 단일 파일로 이동 가능하다.
**NFR-8.2** 설정 파일과 저장소 경로는 설정으로 지정 가능하다.
**NFR-8.3** OS 스케줄러에 의한 비대화형 실행을 지원한다.

### 11.9 테스트 가능성

**NFR-9.1** 지표 계산은 외부 네트워크 없이 고정 입력으로 검증 가능하다.
**NFR-9.2** 수집 계층은 응답을 대체 가능한 형태로 구성하여 네트워크 없이 검증 가능하다.
**NFR-9.3** 결측·중복·부분 실패 상황을 재현하는 테스트를 포함한다.

## 14. 완료 기준

이번 버전은 아래를 모두 충족할 때 완료로 판정한다.

1. `init` 실행으로 설정된 기간의 1분봉·프리미엄 인덱스·metrics가 적재되고, 결측이 `data_gap`에 기록된다.
2. `init` 중단 후 재실행 시 이어서 적재된다.
3. `sync` 실행으로 마지막 적재 시각 이후 구간이 추가되며, 반복 실행이 데이터를 손상시키지 않는다.
4. `summary` 실행으로 FR-4.1의 모든 섹션을 포함한 JSON이 생성된다.
5. 네트워크를 차단한 상태에서 `summary`를 실행하면, 저장된 데이터로 요약이 생성되고 `gaps`에 취득 실패가 기록된다.
6. `status` 실행으로 데이터셋별 적재 상태와 미해소 결측이 출력된다.
7. 설정 파일에서 ZigZag `k`값을 변경하면 스윙 결과와 `meta`의 파라미터 기록이 함께 변경된다.
8. 요약 JSON에 확률·승률·기대값 필드와 방향 판정 필드(CLAUDE.md 금지어 목록)가 존재하지 않는다.
9. FR-3.x 지표에 대한 고정 입력 기반 테스트가 통과한다.
10. REST 적재 후 `kline_1m`과 `premium_index_1m`에 마감되지 않은 봉이 없다.
11. `metrics_5m`의 빈 칸이 컬럼 단위로 `data_gap`에 기록되고, 이후 해당 칸을 채우는 적재가 오면 채워지고 결측이 해소된다.

## 15. 미해결 사항과 리스크

### 15.1 파라미터 미검증

ZigZag의 `k=2.0`, ATR 기간, 레짐 임계값은 관행적 기본값이며 이 시장·타임프레임에서 검증되지 않았다. 검증 단계에서 조정 대상이다. 설정 분리(FR-6.3)로 조정 비용을 낮춘다.

### 15.2 아카이브 결측

metrics 아카이브의 행 결측은 드물지만(8.4), 2025-07 이전에는 top trader 비율 등의 빈 칸이 수백 일에 걸쳐 존재한다. 워밍업 구간이 이 기간에 걸리면 해당 컬럼 기반 지표의 결손 비율이 높아진다. `status`로 결측률을 모니터링한다.

### 15.3 청산 부재의 영향

청산 데이터 없이는 급격한 가격 반전의 원인을 직접 관측할 수 없다. 이번 버전은 가격 기반 충격 판정(FR-3.8)으로 대체하며, 이 판정의 신뢰도는 검증되지 않았다.

### 15.4 미완성 봉 처리

판단 시점은 봉 마감과 일치하지 않는다. 진행 중인 봉의 지표값은 봉 마감 시 변경된다. 시스템은 이를 구분 표기하나, 해석 주체가 이를 고려해야 한다.

### 15.5 API 변경

외부 API 제약은 변경될 수 있다. 8.2의 제약값은 2026-09 기준이며, 변경 시 NFR-6.2에 따라 상수/설정 수정으로 대응한다.

### 15.6 공식 문서로 확인되지 않은 항목

아래 항목은 작성 환경에서 공식 문서에 접근하지 못해 2차 자료로만 확인했다. 구현 전에 공식 문서로 확인한다.
- `/fapi/v1/klines`, `/fapi/v1/premiumIndexKlines`의 limit 최대값(1000 또는 1500)과 구간별 가중치
- `/fapi/v1/premiumIndex`의 가중치와 응답 필드명(`lastFundingRate`, `nextFundingTime`)
- REST 파생 지표 엔드포인트의 응답 필드명(8.4 매핑표)

### 15.7 metrics 컬럼 매핑 미검증

8.4의 아카이브-REST-스키마 매핑은 추정이다. 매핑이 틀리면 롱숏 비율이 서로 뒤바뀐 채 저장된다. 구현 시 최근 30일 겹치는 구간에서 아카이브와 REST 값을 대조하는 검증을 1회 수행하고, 결과를 이 절에 기록한다.

### 15.8 실행 위치

사용자 메인 PC에서 실행하는 것을 전제로 한다. `sync` 스케줄은 선택 사항이므로 PC가 꺼져 있어도 데이터는 유실되지 않으며, `summary` 실행 시 증분 수집으로 보완된다. 바이낸스는 일부 지역의 접속을 제한하므로 실행 위치를 바꿀 때는 접속 가능 여부를 먼저 확인한다.

## 부록 A. 계산 정의와 이벤트 목록 (v0.2)

v0.1 초안에 검토 결과를 반영한 판이다. 이 부록이 확정되기 전에는 FR-3.2 ~ FR-3.12의 지표를 구현하지 않는다.

### A.0 작성 원칙

- 관행적 기본값을 사용하되, 이 시장·타임프레임에서 검증되지 않았음을 항목마다 명시한다.
- 모든 정의는 고정 입력에서 기대 출력을 손으로 계산할 수 있는 수준까지 내려쓴다(공식, 초기값, 동점 처리, 경계 조건, 기본값).

각 항목의 **검증 상태** 표기:
- `미검증`: 관행값 또는 작성자 판단. 검증 단계에서 조정 대상.
- `확인 필요`: 외부 사실(API 필드 등)에 의존하며 공식 문서 확인 전.

---

### A.1 공통 규칙

**A.1.1 타임프레임과 봉 경계**
- 대상 타임프레임: 설정값 `indicators.timeframes` (기본 `15m`, `30m`, `1h`, `1d`).
- 봉 경계는 UTC 기준 정렬이다. `open_time mod (TF 길이) = 0`인 1분봉부터 TF 길이만큼을 하나의 봉으로 합성한다. `1d`는 00:00 UTC 시작.
- 합성 규칙: open = 구간 내 첫 1분봉 open, high = 최대 high, low = 최소 low, close = 마지막 1분봉 close, volume·quote_volume·taker 계열 = 합.

**A.1.2 마감 봉 원칙과 기준 시각**
- 모든 지표와 이벤트는 **마감된 봉**으로만 계산한다.
- 기준 시각 `ref_time` = 가장 최근 마감 1분봉의 `close_time + 1` (다음 분의 시작 시각, 정수 분 경계). 기준 가격 `ref_price` = 그 봉의 close.
- TF별 "현재 봉"은 `close_time < ref_time`인 마지막 TF 봉이다. 진행 중인 TF 봉은 지표 계산에 포함하지 않으며, 요약에 `is_closed: false`로 별도 표기한다.

**A.1.3 결손 처리**
- 합성 봉의 `missing_ratio` = 구간 내 결측 1분봉 수 / TF 길이(분).
- `missing_ratio = 1`인 봉은 **부재 봉**이다. 값이 없으며 계산에 사용하지 않는다.
- `0 < missing_ratio < 1`인 봉은 존재하는 1분봉으로 합성하고 `missing_ratio`를 보존한다.
- 지표의 `gap_ratio` = 계산 창 안의 결측 1분봉 수 합 / (창 봉 수 × TF 길이(분)). 봉 단위가 아니라 분 단위로 센다(FR-3.0).
- 계산 창에 부재 봉이 포함되면 해당 지표값은 `null`, 사유는 `window_contains_absent_bar`.
- 재귀형 지표(ATR)는 부재 봉 이후 초기화한다(A.2.1).

**A.1.4 분모 0**
- 분모가 0이 되는 모든 계산은 `null`을 반환하고 사유 `zero_denominator`를 기록한다. 0이나 무한대로 대체하지 않는다.

**A.1.5 비교 규칙**
- "돌파", "초과"는 명시가 없는 한 **엄격 부등호**다. 같으면 성립하지 않는다.
- 부동소수점 동등 비교는 원값을 그대로 사용한다. 반올림은 출력 직렬화 단계에서만 한다.

**A.1.6 백분위 순위 (공용)**
- 입력: 현재값 `x`와 비교 표본 `S`(현재값 포함, 크기 `M`).
- `B` = S에서 x보다 작은 값의 수, `E` = S에서 x와 같은 값의 수(자기 자신 포함).
- `pct = 100 × (B + 0.5 × E) / M`. 범위 (0, 100).
- S의 크기가 M 미만이면 `null`, 사유 `insufficient_history`.

예: S = [1, 2, 2, 3, 5], x = 2 → B = 1, E = 2 → pct = 100 × (1 + 1)/5 = 40.

**A.1.7 ATR 정규화 시점**
- 특정 봉 t를 평가하거나 정규화할 때는 **직전 마감 봉의 ATR(`ATR_{t−1}`)**을 쓴다. 봉 t 자신의 TR이 분모에 섞이는 자기 참조를 막기 위함이다. 적용 대상: 캔들 구조, ZigZag 임계값, 돌파 거리, shock.
- 기준 시각에서의 거리를 잴 때는 해당 TF의 **마지막 마감 봉 ATR**을 쓴다. 적용 대상: 레벨 정규화, 잠정 파동 거리.
- 사용할 ATR이 `null`이면 그 값도 `null`이다.

### A.2 변동성

**A.2.1 ATR** — 검증 상태: `미검증`(기간)

- True Range: `TR_t = max(H_t − L_t, |H_t − C_{t−1}|, |L_t − C_{t−1}|)`. 직전 봉이 없으면 `TR_t = H_t − L_t`.
- 평활: Wilder.
  - 첫 값: 사용 가능한 첫 `n`개 TR의 산술평균. 이 값은 `n`번째 TR 봉에 부여한다.
  - 이후: `ATR_t = (ATR_{t−1} × (n − 1) + TR_t) / n`.
  - 첫 값 이전은 `null`.
- 부재 봉을 만나면 재귀를 중단하고, 부재 봉 다음부터 첫 값 산출을 다시 시작한다.
- 기본값: `n = 14`. TF별 독립 계산.

예 (n = 3):

| t | H | L | C | TR | ATR |
|---|---|---|---|---|---|
| 1 | 10 | 8 | 9 | 2 | null |
| 2 | 11 | 9 | 10 | 2 | null |
| 3 | 12 | 9 | 11 | 3 | (2+2+3)/3 = 2.3333… |
| 4 | 11 | 10 | 10 | 1 | (2.3333…×2 + 1)/3 = 1.8888… |

**A.2.2 Parkinson 변동성** — 검증 상태: `미검증`(기간·룩백)

- 봉별: `r_t = ln(H_t / L_t)`. `H_t = L_t`이면 `r_t = 0`.
- `σP_t = sqrt( Σ_{i=t−N+1..t} r_i² / (4 × ln 2 × N) )`.
- 단위: 봉당 로그 변동성. **연율화하지 않는다.**
- 백분위: 최근 `M`개 `σP`(현재 포함)에 대해 A.1.6 적용.
- 기본값: `N = 20`, `M = 100`.

### A.3 가격 구조

**A.3.1 캔들 구조** — 검증 상태: `미검증`(보고 봉 수)

- `range = H − L`. `range = 0`이면 아래 비율은 모두 `null`.
- `upper_wick_ratio = (H − max(O, C)) / range`
- `lower_wick_ratio = (min(O, C) − L) / range`
- `body_ratio = |C − O| / range`
- `body_atr = |C − O| / ATR_{t−1}` (A.1.7)
- `range_atr = range / ATR_{t−1}`
- 보고 범위: TF별 최근 `K`개 마감 봉. 기본 `K = 5`.

**A.3.2 스윙 (ATR-ZigZag)** — 검증 상태: `미검증`(k)

입력: TF별 마감 봉의 H, L과 `ATR_{t−1}`. `ATR_{t−1}`이 `null`인 봉은 건너뛴다.

임계값: `θ_t = k × ATR_{t−1}` (A.1.7).

상태: `dir ∈ {none, up, down}`, 후보 극점 `(price, bar)`.

**후보 재설정 규칙**: 극점을 확정하면, 새 후보는 **확정한 극점의 봉부터 봉 t까지 구간**의 반대쪽 극값이다. 스윙 고점을 확정했으면 그 구간의 최저 low와 그 봉, 스윙 저점을 확정했으면 최고 high와 그 봉이다. 같은 값이 여러 봉에 있으면 가장 이른 봉을 쓴다.

1. **초기 (`dir = none`)**: ATR을 쓸 수 있는 첫 봉부터 최고 high `HH`와 그 봉, 최저 low `LL`과 그 봉을 추적한다. 봉 t에서
   1. 봉 t를 포함해 `HH`와 `LL`을 갱신한다. 같은 값이면 기존 봉을 유지한다.
   2. 조건 A: `H_t − LL ≥ θ_t`. 조건 B: `HH − L_t ≥ θ_t`.
   3. A만 성립하면 LL을 **확정 스윙 저점**으로 기록하고 `dir = up`, 후보는 재설정 규칙으로 정한다.
   4. B만 성립하면 HH를 **확정 스윙 고점**으로 기록하고 `dir = down`, 후보는 재설정 규칙으로 정한다.
   5. 둘 다 성립하면 LL과 HH 중 **먼저 발생한 쪽**을 확정한다. `HH`와 `LL`이 같은 봉이면 이번 봉에서는 확정하지 않는다. 봉 하나의 범위만으로는 어느 쪽이 먼저인지 알 수 없기 때문이다.
   6. 확정했으면 4번의 재검사를 수행한다.
2. **`dir = up`**: 봉 t에서 순서대로
   1. (확장) `H_t > 후보.price`이면 후보 = (H_t, t). 같으면 기존 후보 유지.
   2. (반전) `후보.price − L_t ≥ θ_t`이면 후보를 **확정 스윙 고점**으로 기록, `dir = down`, 후보는 재설정 규칙으로 정한다. 이어서 4번의 재검사를 수행한다.
3. **`dir = down`**: 2의 대칭.
   1. (확장) `L_t < 후보.price`이면 후보 = (L_t, t).
   2. (반전) `H_t − 후보.price ≥ θ_t`이면 **확정 스윙 저점** 기록, `dir = up`, 후보는 재설정 규칙으로 정한다. 이어서 4번의 재검사를 수행한다.
4. **같은 봉 재검사**: 확정 직후 새 후보의 봉이 t보다 앞서면, 새 후보에 대해 봉 t의 반전 조건(2.2 또는 3.2)을 다시 검사한다. 성립하면 확정과 후보 재설정을 반복한다. 새 후보의 봉이 t이면 재검사하지 않는다(같은 봉 안의 순서는 알 수 없음).
5. 한 봉에서 확장과 반전이 모두 가능한 경우 확장 → 반전 → 재검사 순서를 따른다. 따라서 같은 봉이 극점이자 반대 방향 후보가 될 수 있다.

예 (초기 단계, 5번 봉의 고점을 놓치지 않는 경우): LL이 1번 봉, HH가 5번 봉이고 10번 봉에서 조건 A와 B가 모두 성립하면, 먼저 발생한 LL을 확정한다. 새 후보는 1~10번 봉의 최고 high인 HH(5번 봉)이다. 재검사에서 `HH − L_10 ≥ θ_10`이 성립하므로 HH도 확정 스윙 고점으로 기록하고 `dir = down`, 후보는 5~10번 봉의 최저 low가 된다.

출력:
- 확정 스윙 목록: `type ∈ {swing_high, swing_low}`, `price`, `bar_time`(극점 봉), `confirmed_time`(확정 봉).
- 잠정 파동: `dir`, 후보 `price`, `bar_time`, `(ref_price − 후보.price) / ATR` (ATR은 A.1.7의 기준 시각 ATR).
- 기본값: `k = 2.0`. ZigZag의 ATR은 같은 TF의 ATR.

**A.3.3 구조 상태** — 검증 상태: `미검증`

최근 확정 스윙 고점 2개(`SH1` 최신, `SH0` 이전)와 저점 2개(`SL1`, `SL0`)로 판정한다.

| 조건 | `structure_state` |
|---|---|
| SH1 > SH0 그리고 SL1 > SL0 | `higher_highs_higher_lows` |
| SH1 < SH0 그리고 SL1 < SL0 | `lower_highs_lower_lows` |
| 그 외 (같음 포함) | `mixed` |
| 고점 또는 저점이 2개 미만 | `insufficient` |

구조 상태는 새 스윙이 확정될 때만 갱신된다.

**A.3.4 돌파와 BOS/MSS** — 검증 상태: `미검증`(변위 배수·기간)

돌파 판정 대상은 **아직 돌파되지 않은** 가장 최근 확정 스윙 고점 `SH`와 저점 `SL`이다. 판정은 그 스윙이 확정된 봉(`confirmed_time`)의 **다음 봉부터** 한다.

- `close_above_swing_high`: `C_{t−1} ≤ SH` 그리고 `C_t > SH`
- `close_below_swing_low`: `C_{t−1} ≥ SL` 그리고 `C_t < SL`
- 종가가 극점과 같으면 돌파가 아니다.
- 돌파된 스윙은 `broken`으로 표시하며 다시 돌파 이벤트를 만들지 않는다.

변위: `displacement_mult = |C_t − O_t| / mean(|C_i − O_i|, i = t−N..t−1)`. 평균에 봉 t를 포함하지 않는다. 평균이 0이면 `null`.

분류:

| 돌파 방향 | 구조 상태 | 변위 조건 | `break_kind` |
|---|---|---|---|
| 위 | higher_highs_higher_lows | 무관 | `BOS` |
| 아래 | lower_highs_lower_lows | 무관 | `BOS` |
| 위 | lower_highs_lower_lows | 충족 | `MSS` |
| 아래 | higher_highs_higher_lows | 충족 | `MSS` |
| 위/아래 | 반대 구조 | 미충족 | `break_no_displacement` |
| 위/아래 | mixed / insufficient | 무관 | `break_unclassified` |

- 변위 충족: `displacement_mult ≥ m`.
- 기본값: `m = 1.5`, `N = 20`.

**A.3.5 되돌림** — 검증 상태: `미검증`

기준 파동: 가장 최근 확정 스윙 2개 `P_a`(이전), `P_b`(최신). 두 스윙은 서로 반대 유형이다.

- `P_b`가 swing_high(상승 파동): `depth = (P_b.price − ref_price) / (P_b.price − P_a.price)`
- `P_b`가 swing_low(하락 파동): `depth = (ref_price − P_b.price) / (P_a.price − P_b.price)`
- **0~1로 자르지 않는다.** 음수는 기준 파동 극점을 넘어선 상태, 1 초과는 파동 시작점을 넘어선 상태다.
- `time_ratio = (현재 TF 봉 인덱스 − P_b 봉 인덱스) / (P_b 봉 인덱스 − P_a 봉 인덱스)`
- 분모 0이면 `null`.

### A.4 레짐

FR-3.7의 분류를 **두 개의 독립 축**으로 출력한다. 두 축을 하나의 레이블로 합성하지 않는다(CLAUDE.md R-7).

**A.4.1 효율성 축** — 검증 상태: `미검증`(기간·임계값)

- `ER_t = |C_t − C_{t−n}| / Σ_{i=t−n+1..t} |C_i − C_{i−1}|`. 분모 0이면 `null`.
- 분류:

| 조건 | `efficiency_state` |
|---|---|
| ER ≥ `er_trend` | `trend` |
| ER ≤ `er_range` | `range` |
| 그 사이 | `transition` |

- 기본값: `n = 10`, `er_trend = 0.5`, `er_range = 0.3`.
- 히스테리시스를 적용하지 않는다.

**A.4.2 변동성 축** — 검증 상태: `미검증`(임계값)

A.2.2의 Parkinson 백분위를 사용한다.

| 조건 | `volatility_state` |
|---|---|
| pct ≥ `vol_high` | `expansion` |
| pct ≤ `vol_low` | `compression` |
| 그 사이 | `normal` |

- 기본값: `vol_high = 80`, `vol_low = 20`.

**A.4.3 지속 봉 수**

- 각 축의 상태가 현재 봉까지 연속으로 같은 봉 수. 현재 봉 포함.
- `null` 봉을 만나면 계수를 중단한다.

**A.4.4 shock** — 검증 상태: `미검증`(전 항목)

판정 대상 TF: 설정값 `regime.shock.timeframes` (기본 `15m`, `30m`, `1h`). `1d`는 기본 판정 대상이 아니다.

봉 t에서 다음 중 하나가 성립하면 shock 발동:

- **(a) 꼬리 조건**: `max(upper_wick_ratio_t, lower_wick_ratio_t) ≥ w_th` 그리고 `range_atr_t ≥ r_th`
- **(b) 급속 반전 조건**: 같은 TF에서 `close_above_swing_high`와 `close_below_swing_low`가 봉 간격 `≤ g` 안에 모두 발생하고, 그중 늦은 쪽이 봉 t

지속: 발동 봉을 포함해 `D`개 봉 동안 활성. 활성 중 재발동하면 재발동 봉부터 `D`개로 연장.

활성 중 효과: 해당 TF의 `efficiency_state`를 `shock`으로 덮어쓴다. ER 원값은 그대로 출력한다. `volatility_state`는 덮어쓰지 않는다.

기본값: `w_th = 0.6`, `r_th = 1.5`, `g = 2`, `D = 4`.

**원 정의(PRD v1.1 FR-3.8)에서 바뀐 점**
- (a)의 `range_atr` 조건을 추가했다. 꼬리 비율만 보면 거래량이 적은 작은 봉에서 과다 발동하기 때문이다.
- (b)를 "1~2봉 내 반대 방향 MSS"에서 "변위·구조 조건 없는 양방향 돌파"로 바꿨다. ZigZag의 후행성 때문에 짧은 간격 안에 양쪽 스윙이 모두 돌파되는 것 자체가 드문데, 변위까지 요구하면 사실상 발동하지 않는다. 또 MSS 분류는 구조 상태에 의존하는데, 급반전 국면에서는 구조 상태가 `mixed`인 경우가 많아 조건이 성립하지 않는다. shock은 방향 판단이 아니라 판정 보류 표시이므로 넓게 잡는다.

### A.5 파생 지표

**A.5.1 미결제약정 4분면** — 검증 상태: `미검증`(기간·불감대), `확인 필요`(metrics 시각 의미)

- OI 값: `metrics_5m.sum_open_interest`(계약 수). 명목값을 사용하지 않는다.
- `OI_t`: `ts ≤ ref_time`인 가장 최근 행의 값.
- `Px_t`: `close_time = ts − 1`인 1분봉(스냅샷 시각 직전에 마감한 봉)의 close. `open_time = ts`인 봉의 종가는 1분 뒤의 가격이므로 쓰지 않는다.
- 산출 기간 `P`마다:
  - `OI_{t−P}`: `ts − P`에 해당하는 행. 그 행이 없거나 값이 NULL이면 `dOI`는 `null`, 사유 `source_gap`. 가장 가까운 행으로 대체하지 않는다(R-3).
  - `Px_{t−P}`: `close_time = ts − P − 1`인 1분봉의 close. 없으면 `null`.
  - `dOI = (OI_t − OI_{t−P}) / OI_{t−P}`
  - `dPx = (Px_t − Px_{t−P}) / Px_{t−P}`
- 불감대: `|dOI| < oi_band`이면 OI 무변화, `|dPx| < px_band`이면 가격 무변화.

| dOI | dPx | `quadrant` |
|---|---|---|
| 증가 | 상승 | `oi_up_price_up` |
| 증가 | 하락 | `oi_up_price_down` |
| 감소 | 상승 | `oi_down_price_up` |
| 감소 | 하락 | `oi_down_price_down` |
| 무변화 또는 가격 무변화 | — | `indeterminate` |

- `dOI` 또는 `dPx`가 `null`이면 `quadrant`도 `null`이다.
- 기본값: `P ∈ {1h, 4h}`, `oi_band = 0.001`(0.1%), `px_band = 0.001`.
- 원값 `dOI`, `dPx`를 함께 출력한다.
- 주: metrics의 `create_time`이 구간 시작 시각인지 종료 시각인지 확인되지 않았다. 확인 전까지 스냅샷 시각으로 간주한다.

**A.5.2 프리미엄 인덱스** — 검증 상태: `미검증`(기간·룩백)

- 단위 변환: `bp = 값 × 10000`.
- **현재값**: 마감된 가장 최근 프리미엄 1분봉의 close(bp). 신선도를 맡는다.
- **변화량**: 기간 `W`마다 `현재값 − (현재 1분봉보다 W 앞선 1분봉의 close)` (bp 차이). **비율로 계산하지 않는다.** 비교 대상 1분봉이 없으면 `null`.
- **평활값**: 평활 TF(기본 `15m`) 봉마다, 구간 내 1분 프리미엄 close의 산술평균(bp). 결측 분이 있으면 있는 값으로 평균을 내고 `missing_ratio`를 표기한다. 전부 없으면 부재 봉이다.
- **분포 위치**: 마지막 마감 평활 봉의 평활값을, 최근 `L`개 평활값(현재 포함)에 대한 A.1.6 백분위로 산출한다. 창에 부재 봉이 있으면 A.1.3에 따라 `null`. 안정된 상대 위치를 맡는다.
- 0 기준 부호 전환은 판정하지 않는다. 실측상 최근 1년 1분봉 종가의 99.2%가 음수이므로 0은 중립 기준이 아니다(8.4). 절대 수준은 펀딩비(A.5.3)가 제공한다.
- 기본값: `W ∈ {15m, 1h, 4h}`, 평활 TF `15m`, `L = 672`(15분 봉 7일).

평활을 택한 이유: 흔들림의 원인은 샘플 12개짜리 1분 값의 측정 노이즈다. 유지 조건은 원인을 그대로 둔 채 판정만 늦추고 상태와 파라미터를 늘린다. 평활은 원인을 직접 줄인다. 평활 TF를 15분으로 맞추면 판정 주기가 결정 타임프레임과 일치하고, 이벤트 보고 기간(15m)을 그대로 쓸 수 있다.

**A.5.3 펀딩 (비용 정보)** — 검증 상태: `확인 필요`(필드명)

- 출처: `/fapi/v1/premiumIndex`, 필드 `lastFundingRate`, `nextFundingTime`.
- 출력: `funding_rate_bp = lastFundingRate × 10000`, `minutes_to_next_funding = (nextFundingTime − ref_time) / 60000` (정수 내림).
- 판단 지표가 아니라 보유 비용 정보다. 이벤트를 만들지 않는다.

### A.6 VWAP — 검증 상태: `미검증`(기준점 선택)

- 기준: **롤링 창**. UTC 일간 기준점은 00:00에 불연속이 발생하므로 채택하지 않는다.
- `VWAP = Σ quote_volume / Σ volume`, 합산 대상은 `ref_time` 이전 마감 1분봉 `V`개.
- `Σ volume = 0`이면 `null`.
- 창 내 결측 1분봉 비율을 `gap_ratio`로 출력한다.
- 기본값: `V = 1440`(24시간).
- 주: v2의 VWAP는 현물 기준이었으나 v3는 선물 1분봉 기준이다.

### A.7 레벨 — 검증 상태: `미검증`(전 항목)

**A.7.1 후보 출처**

| 출처 | 내용 | 기본 개수 |
|---|---|---|
| `swing_15m` | 15m 확정 스윙 고점·저점 | 최근 각 5개 |
| `swing_1h` | 1h 확정 스윙 고점·저점 | 최근 각 5개 |
| `vwap_24h` | A.6 | 1 |
| `high_24h`, `low_24h` | `ref_time` 이전 마감 1분봉 `V_r`개의 최고 high, 최저 low (기본 `V_r = 1440`) | 각 1 |

`broken` 표시된 스윙도 후보에 포함하며 `broken` 여부를 함께 기록한다.

**A.7.2 정규화 기준**

모든 레벨의 거리와 폭은 **기준 시각의 1h ATR**(마지막 마감 1h 봉의 ATR, A.1.7)로 정규화한다. 서로 다른 출처의 레벨을 같은 척도로 비교하기 위함이다. 이 ATR이 `null`이면 레벨 목록 전체가 `null`이다.

**A.7.3 병합**

1. 후보를 가격 오름차순으로 정렬한다.
2. 첫 후보로 클러스터를 시작한다.
3. 다음 후보 가격 − 현재 클러스터 최소 가격 `< merge_dist × ATR_1h`이면 현재 클러스터에 추가한다. 아니면 새 클러스터를 시작한다.
4. 모든 후보를 처리할 때까지 반복한다.

클러스터 최소 가격 기준을 쓰므로 클러스터 폭은 `merge_dist × ATR_1h` 미만으로 제한된다.

**A.7.4 레벨 출력**

- `center` = 클러스터 구성원 가격의 산술평균 (가중치 없음)
- `zone = [min − w × ATR_1h, max + w × ATR_1h]`
- `distance_atr = (center − ref_price) / ATR_1h`. 양수는 기준 가격 위, 음수는 아래.
- `position`: 레벨을 주어로 표기한다. ref_price가 zone 안이면 `inside`, zone 하단보다 ref_price가 낮으면 `level_above`, zone 상단보다 ref_price가 높으면 `level_below`.
- `sources`: 구성원 출처 목록, `source_count`: 서로 다른 출처 수.
- 보고 범위: ref_price 위아래 각각 가장 가까운 `R`개.
- 기본값: `merge_dist = 0.5`, `w = 0.25`, `R = 5`.
- 레벨 강도 점수는 산출하지 않는다(FR-3.11).

### A.8 이벤트

**A.8.1 공통 필드**

| 필드 | 내용 |
|---|---|
| `type` | 이벤트 유형 |
| `family` | `price_structure` / `regime` / `derivatives` / `level` |
| `tf` | 타임프레임 |
| `bar_time` | 발생 봉의 open_time |
| `bars_ago` | 현재 TF 봉 기준 경과 봉 수 (현재 봉 = 0) |
| `measures` | 유형별 측정값 |

**A.8.2 보고 기간**

TF별로 최근 `R_tf`개 마감 봉 안에서 발생한 이벤트만 보고한다. 기본값: `15m = 16`, `30m = 8`, `1h = 8`, `1d = 3`. `quadrant_change`는 별도 설정값(기본 240분)을 쓴다. — 검증 상태: `미검증`

**A.8.3 이벤트 목록**

| type | family | TF | 발생 조건 | measures |
|---|---|---|---|---|
| `swing_confirmed` | price_structure | 전체 | A.3.2에서 스윙 확정 | `swing_type`, `price`, `extreme_bar_time`, `lag_bars`(극점→확정 봉 수) |
| `structure_break` | price_structure | 전체 | A.3.4 돌파 발생 | `side`(`above_swing_high`/`below_swing_low`), `break_kind`, `swing_price`, `close_beyond_atr`(\|C_t − swing\| / ATR_{t−1}), `displacement_mult` |
| `volume_spike` | price_structure | 15m, 30m, 1h | `vol_t / mean(vol, t−N..t−1) ≥ v_th` | `volume_mult` |
| `efficiency_state_change` | regime | 전체 | `efficiency_state`가 직전 봉과 다름 | `from`, `to`, `er` |
| `volatility_state_change` | regime | 전체 | `volatility_state`가 직전 봉과 다름 | `from`, `to`, `pct` |
| `shock_start` | regime | shock 판정 TF | A.4.4 발동 (연장 제외) | `trigger`(`wick`/`rapid_reversal`/`both`), `wick_ratio`, `range_atr` |
| `level_wick_into_zone` | level | 레벨 이벤트 TF | 봉의 high 또는 low가 zone에 들어갔으나, `C_{t−1}`과 `C_t`가 모두 zone 밖 같은 쪽 | `level_center`, `penetration_atr`, `source_count` |
| `level_close_into_zone` | level | 레벨 이벤트 TF | `C_{t−1}`이 zone 밖, `C_t`가 zone 안 | `level_center`, `source_count` |
| `level_close_through_zone` | level | 레벨 이벤트 TF | `C_{t−1}`과 `C_t`가 zone의 서로 반대편 밖 | `level_center`, `close_beyond_atr`, `source_count` |
| `quadrant_change` | derivatives | 5m 기준 | 기간 P의 `quadrant`가 직전 metrics 시각과 다름 (둘 다 `null`이 아닐 때) | `period`, `from`, `to`, `d_oi`, `d_px` |
| `premium_extreme` | derivatives | 평활 TF (15m) | 직전 평활 봉에서는 극단 구간이 아니었고, 이번 평활 봉에서 극단 구간 (백분위 ≥ `p_high` 또는 ≤ `p_low`) | `side`(`high`/`low`), `value_bp`(평활값), `pct` |

- 레벨 이벤트 TF: 설정값 `events.level.timeframes` (기본 `15m`).
- 레벨 이벤트는 **기준 시각의 레벨 목록**(A.7)으로 보고 기간 안의 봉을 판정한다. 과거 봉 시점의 레벨을 재구성하지 않는다.
- `penetration_atr`: zone 가장자리부터 봉의 극값까지 zone 안쪽으로 들어간 거리 / 기준 시각의 ATR_1h.
- 레벨 이벤트의 `close_beyond_atr`: zone 가장자리부터 `C_t`까지의 거리 / 기준 시각의 ATR_1h.
- `volume_spike` 기본값: `N = 20`, `v_th = 2.0`.
- `premium_extreme` 기본값: `p_high = 95`, `p_low = 5`. 보고 기간은 평활 TF의 보고 기간(`15m = 16`)을 따른다.
- 검증 상태: 모든 임계값 `미검증`.

**A.8.4 제외한 이벤트**

| 후보 | 제외 사유 |
|---|---|
| 프리미엄 0 기준 부호 전환 | 실측상 1년 중 양수 시간이 0.8%로 사실상 발동하지 않음. 15분 평활 백분위 기준 `premium_extreme`으로 대체 |

**A.8.5 명명 규칙**

모든 type, state, side 값은 **관측된 사실을 서술**하며 방향 판단을 함의하지 않는다. `bullish`, `bearish`, `long_signal`, `buy`, `sell`, `support`, `resistance` 등 행동이나 역할을 함의하는 단어를 사용하지 않는다. `support`/`resistance`는 레벨의 역할을 단정하므로 제외하고 `level_above`/`level_below`로 표기한다. 금지어는 CLAUDE.md R-2 목록을 따른다.
